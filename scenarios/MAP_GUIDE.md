# 협력 맵 제작 가이드 (v1, 2026-10-13)

새 시나리오 맵을 만들 때 따르는 기준입니다. 두 가지에 근거합니다.
1. **ARC-AGI-3**의 설계 기조: 설명 없이 상호작용으로 규칙을 알아내게 하고, 레벨을 쌓아 난이도를 나눕니다.
2. **1·2차 시험 실행에서 모델들이 못 깬 맵의 공통점**: 아래 2절의 표에 정리했습니다.

## 0. 합격 기준 (모든 새 맵)
| 기준 | 확인 방법 |
|---|---|
| **사람은 풀 수 있다** | 정답 스크립트(`solution`)와 실수 후 복구 스크립트(`mistake`)가 클리어해야 합니다(`python -m scenarios --check`). 가능하면 두 사람이 `play.py`로 직접 깨 봅니다. |
| **기준 모델 3종 중 1개 이하만 깬다** | gpt-6-luna, claude-haiku-5.5, glm-5.3-flash(`--reasoning-effort medium`)로 각각 한 번씩, 권장 step으로 실행합니다. 모든 단계를 깬 모델이 **2개 이상이면 불합격**이고 난이도를 올립니다. |
| **우연이나 무차별 대입으로 깰 수 없다** | 대칭 시작 금지(아래 3-6). 무작위 입력으로 깰 확률은 step 예산 안에서 1% 미만이어야 합니다. |
| **혼자서는 못 깬다** | 각 단계에 두 에이전트가 모두 필요한 조건이 최소 하나 있어야 합니다(`--solo-agent`로 확인). |

## 1. ARC-AGI-3에서 가져오는 기조
ARC-AGI-3(2026-03 공개)는 지시, 목표 설명, 규칙 설명 없이 에이전트를 게임에 넣습니다. 에이전트는 관찰하고 행동하고 결과를 보며 규칙을 알아내야 합니다. 레벨마다 새 메커니즘을 하나씩 도입하고, 뒤 레벨일수록 앞에서 배운 메커니즘을 결합합니다. 점수는 사람 기준 대비 행동 효율 `min(1, 사람 행동 수 / AI 행동 수)²`이고, 사람의 5배를 넘으면 0점입니다. 언어, 숫자, 문화적 기호 같은 사전 지식 없이 기본 인지(물체성, 기하, 단순 물리, 행위자성)만으로 풀 수 있게 만듭니다.

우리 맵에는 다음처럼 적용합니다.

1. **난이도 분할 = 단계형 맵** (`rules.stages`). 단계는 셋 이상으로 둡니다.
   - **1단계(튜토리얼):** 이 맵의 핵심 메커니즘 하나만 둡니다. 1단계는 대부분의 모델이 깨도 됩니다.
   - **2단계:** 두 번째 메커니즘을 도입하거나, 1단계 메커니즘을 공간적으로 어렵게 합니다.
   - **3단계 이상:** 앞 단계의 메커니즘을 **결합**한 새 상황입니다. 이 단계에서 모델이 걸러져야 합니다.
2. **설명하지 않습니다.**
   - 목표만 짧게 줍니다(예: "panel_3을 풀어라").
   - 물체가 어떻게 작동하는지 쓰지 않습니다(`explain()` 쓰지 않기). 확인 응답이 필요하다, 정보가 틀릴 수 있다 같은 전략 힌트나, 이 쪽지가 상대를 위한 것이라는 안내도 넣지 않습니다.
   - 규칙은 행동의 결과(`last_action_result`, `notices`, 문/패널/점수의 변화)로 드러나게 합니다.
   - **(2026-10-13 변경, 모든 맵에 적용)** 물체 종류의 역할은 이제 시스템 프롬프트(`policy.py` `_OBSERVATION_DOC`의
     Object roles)에 공통으로 들어갑니다. 맵의 과제 설명과 단계 안내는 목표만 말합니다. 맵마다 두 버전이 있습니다:
     **힌트 버전**(`<이름>.json`)은 단서에 장치 작동을 구체적으로 알려 주는 힌트를 주고, **힌트 없는 버전**(`<이름>_nohint.json`)은
     퍼즐 자료만 줍니다. 두 버전 모두 현재 상태, 위치/배치, 해결 순서 지시는 쓰지 않습니다. 자세한 기준은 [MAP_HOWTO.md](MAP_HOWTO.md) 6장, 실제 글은 [AGENT_TEXTS.md](AGENT_TEXTS.md).
3. **언어 의존을 줄입니다.**
   - 단서는 문장 대신 숫자, 좌표, 배치로 줍니다.
   - 물체 id나 label이 정답을 암시하지 않게 합니다(예: `plate_for_door_B` 대신 `p1`).
4. **효율을 잽니다.**
   - 권장 step은 정답 스크립트의 약 **3배**로 둡니다(ARC의 5배 상한보다 엄격).
   - 단계별 효율은 `(정답 스크립트 step / 실제 step)²`로 기록합니다.
5. **사람에게는 쉽고 AI에게는 어렵게 만듭니다.** 사람 두 명이 `play.py`로 권장 step의 절반 안에 깰 수 있어야 합니다.

## 2. 못 깬 맵에서 뽑은 어려움의 축
1·2차 시험(로그: `experiment_log/2026-10-12_scenario_trial`, `2026-10-13_scenario_trial2`)에서 실패한 판의 원인입니다.

| 축 | 근거 (실패 판) | 로그에서 본 현상 |
|---|---|---|
| **A. 함께 움직이는 몸 조율** | s07(힌트 없음), s11 | 2인 운반에서 상대가 15 이내에 없어 이동이 23번 막힘(s07). 붙잡기 실패 5번(s11). 말로는 계획을 맞추지만 같은 step에 같은 회전/전진을 하지 못함 |
| **B. 모순된 정보의 교차 검증** | s12 (Haiku, Sonnet 모두 실패) | 서로 읽은 값은 교환하지만 조합 추론을 끝내지 못하고 추측 입력을 반복함(패널 리셋 9~25번) |
| **C. 정보가 있어도 먼저 나누지 않음** | s09, s08 | 메시지 0개. 각자 탐색만 하다가 마지막 한 곳을 못 찾거나(7/8), 대기만 함(noop 377번) |
| **D. 보상 없는 필수 역할** | s08 | 판을 지키는 쪽은 점수가 없어 역할이 생기지 않거나 한쪽에 고정됨 |
| **E. 보이지 않는 동역학 예측** | s11, s10(1차) | 움직이는 목표의 경로를 재구성해 매복하는 데 실패 |
| **F. 긴 교대와 기억 관리** | s02, s06(1차) | 역할 교대가 길어지면 대화 이력이 한도를 넘어 중단됨 |

모델이 **잘 깬 맵의 공통점**도 피해야 할 패턴입니다.
- 짧은 합의 한 번이면 끝남(s01, s05, s10).
- 규칙이 숫자로 명시됨("1 step 이내", "주기").
- 정답이 쪽지에 그대로 있음(s06).
- 매 시도마다 즉시 피드백이 오는 퍼즐(s04).

## 3. 지침
1. **축을 두 개 이상 결합합니다.** 각 맵의 마지막 단계는 위 A~E 중 최소 두 축을 동시에 요구해야 합니다. 축 하나만 쓴 맵은 2차에서 대부분 풀렸습니다.
2. **F 축은 단독으로 쓰지 않습니다.** 대화 이력 한도 초과는 협력 능력과 섞여 해석을 흐립니다. 단계 수와 step 예산을 정해서 긴 과제가 기억 관리만으로 실패하지 않게 합니다.
3. **정보 비대칭은 "읽을 수 있는 쪽"과 "쓸 수 있는 쪽"을 나눕니다.**
   - 단서를 본 사람이 그 단서로 행동할 수 없어야 합니다(C 축).
   - 단서가 상대를 위한 것이라고 알려 주지 않습니다.
4. **피드백은 상대 쪽에 둡니다.** 시도 결과가 행동한 사람에게 바로 보이면 무차별 대입이 됩니다. 결과 화면은 상대 방에 둡니다.
5. **보상 신호를 쓴다면 점수 변화만 줍니다.** 규칙 설명 대신 `rules.show_reward`로 점수가 오르는 것을 보게 합니다. 무엇이 점수를 주는지는 쓰지 않습니다.
6. **대칭을 깹니다.** 두 에이전트의 시작 위치, 목표까지 거리, 맡는 역할을 다르게 합니다. 같은 모델 두 개가 같은 계획을 세워 우연히 맞는 일(2차 s05)을 막기 위해서입니다.
7. **단계마다 둘 다 필요하게 만듭니다.** 한쪽만 움직여도 깨지는 단계는 협력을 재지 못합니다.
8. **실패 상태는 없고 시간만 잃게 합니다.** 기존 원칙과 같습니다. 틀리면 리셋, 밀려남, 다음 주기를 기다리게 합니다.
9. **비밀 값은 `_` 필드에 둡니다.** 정답, 배선, 주기, 경로를 관찰에 노출하지 않습니다(`_disguise`가 지움).
10. **검증을 먼저 하고 합격은 실측으로 판정합니다.**
    - 순서: `solution`/`mistake` 작성 → `--check` → 테스트 → 기준 모델 3종 보정 실행.
    - 2개 이상이 깨면 3단계를 강화하고 다시 실행합니다.

## 4. 새 맵 체크리스트
- [ ] 단계 3개 이상. 1단계는 메커니즘 하나, 마지막 단계는 축 두 개 이상 결합
- [ ] 브리핑에 목표만 있음. 물체 설명, 전략 힌트, "상대를 위한 쪽지" 안내 없음
- [ ] (2026-10-13) 단서는 퍼즐 자료(자료 키)와 구체적인 힌트(다른 키)로 나뉨. _nohint 버전도 풀림. 현재 상태, 위치/배치, 해결 전략은 없음 (MAP_HOWTO.md 6장)
- [ ] 시작 위치나 역할이 비대칭
- [ ] 단서를 보는 쪽과 그 단서로 행동하는 쪽이 다름
- [ ] 피드백이 행동한 쪽이 아닌 쪽에 나타남(해당하는 경우)
- [ ] 권장 step은 정답 스크립트의 약 3배
- [ ] `python -m scenarios --check` 통과, 테스트 통과
- [ ] 기준 모델 3종 중 1개 이하만 전체 클리어 (보정 실행 기록을 experiment_log에 남김)
